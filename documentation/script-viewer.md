# Script Viewer

`src/script_viewer.py` displays the script exported by the [Cue Generator](cue-generator.md) during the live show. It
shows the text block by block together with the mic, audio and light actions and, in colored lanes next to it, the LiSP
cues, X32 snippets and light cues generated for every block. The operator follows the performance by moving from block
to block and always sees which cue comes next.

## Requirements

- Python 3.10 or newer
- `PyQt5` (see `requirements.txt`)

## Usage

```shell
python3 src/script_viewer.py --input out/Hugo.json
```

Without `--input` a file dialog asks for the script. Cancelling the dialog quits the program.

## Command line arguments

| Argument | Required | Default | Description |
| - | - | - | - |
| `--input <file>` | no | file dialog | The script (`.json`) written by the cue generator with `--script-output`. |
| `-h`, `--help` | no | | Prints the help and exits. |

The program exits with an error message if the file cannot be read or is not a script of format version 4.

## The window

The window opens maximized and is titled `Script Viewer - <file name>`.

### Top bar

| Element | Description |
| - | - |
| `Part` selector | Jumps to the first scene of the chosen part (`Vorspann`, `1. Akt`, ...). |
| `Scene` selector | Jumps to the first block of the chosen scene within the selected part. |
| `Settings` | Opens the [settings window](#settings). |
| Position | `Page <page> · Block <n> / <total>` of the current block. |

Both selectors follow the current block, so they always show where in the show it is located.

### Block cards

Every block is shown as a card. The current block is always kept at the same height of the view (at the very top by
default, see [Settings](#settings)), drawn brightly and outlined; all other blocks are dimmed. Near the beginning and the
end of the script, the first and last blocks cannot scroll any further, so the current block may sit lower or higher.

The card shows the character name in capitals above the text. A stage direction of a dialogue is shown in brackets and
italics before the text. `acting` blocks are printed in italics, `command` blocks in bold. The actions of the block are
shown in the cue lanes.

### Cue lanes

Right of the cards, one lane per deck shows which cue is active. A colored bar starts at the block triggering a cue and
runs down to the block triggering the next cue of that deck. LiSP cues are drawn in the background color they have in
LiSP, so neighbouring cues differ; X32 snippets and light cues are drawn in the color of their lane. Beside the start
of its bar, the segment is labeled in large bold letters with a letter and the number of the cue on its deck, as
assigned by the [Cue Generator](cue-generator.md), so the labels match the decks:

| Lane | Number | Label | Label without lane letters |
| - | - | - | - |
| LiSP Cues | Number in the LiSP cue list, from 1 | `L<number>`, e.g. `L1` | `#<number>`, e.g. `#1` |
| X32 Snippets | Snippet slot on the X32, from 0 | `S<number>`, e.g. `S0` | `#<number>`, e.g. `#0` |
| Light Cues | MagicQ cue number, from 1 | `Q<number>`, e.g. `Q1` | `#<number>`, e.g. `#1` |

Which of the two is used is chosen in the [settings](#settings).

If a block triggers several cues of one deck, they share one segment, labeled with the number of the first of them.
A light cue reused by several blocks shows the same number at each of them.

Below the label, a second line in slightly smaller letters shows the name of the cue as generated by the
[Cue Generator](cue-generator.md): `<part> S<scene> B<block>`, e.g. `1. Akt S3 B142` for block 142 in scene 3 of
`1. Akt`. A light cue reused by several blocks is named after the first of them. Names too long for the lane are cut.

Below the name, the actions of the triggering block are listed in the lane of their deck:

| Lane | Symbol | Meaning |
| - | - | - |
| LiSP Cues | `♪ <effect>` | Play the audio effect |
| X32 Snippets | `▲ <actor>` | Unmute the actor's microphone |
| X32 Snippets | `▼ <actor>` | Mute the actor's microphone |
| Light Cues | `☀ <effect>` | Trigger the light effect |

The audio effect is only shown if the LiSP project contains a cue for it (`--lisp-audio` of the cue generator).

If enabled in the [settings](#settings), the `▲` and `▼` lines of the X32 snippet are additionally listed in the LiSP
Cues lane, above the audio effect, as LiSP triggers the snippet. They are only shown there if the block triggers a LiSP
cue.

Below the document, a fixed strip shows the label of the next cue of every visible lane under that lane, in the color
its bar will have. It stays in place while scrolling, so the upcoming cues are always visible. If no cue follows in a
lane, `—` is shown. Right of each label, a counter in the same large
letters shows how many blocks lie ahead until that cue is triggered; `1` means the next block triggers it. Hiding all lanes
also hides the strip.

### LiSP bar

If [LiSP synchronization](#settings) is enabled, a bar across the whole width of the window below the document lets the
Script Viewer start the LiSP cues itself instead of pressing GO in LiSP. This keeps the viewer and LiSP in step, even if
the wrong cue is selected in LiSP or GO is pressed too often or not often enough.

From left to right, directly next to each other at the right edge of the bar:

| Element | Description |
| - | - |
| `Last LiSP cue` | The label and name of the LiSP cue last started with the GO button, e.g. `L5  1. Akt S3 B142`, in its color. `—` until the first GO. |
| `Next LiSP cue` | The LiSP cue the GO button will start, in the same form. `—` if the GO button is disabled. |
| `GO` | Large button at the right edge. Sends `/lisp/cue ,i <number>` to LiSP to start the next LiSP cue. |

The LiSP cue of the current block is the one whose bar in the LiSP Cues lane covers the block, so it is either
triggered by the block itself or by the closest block above it that triggers a LiSP cue. The GO button is enabled, green and
blinking while that cue is not the one started last. Otherwise, and above the first LiSP cue, it is grey and
cannot be pressed. Pressing it starts the cue and disables it again. Moving to another block does nothing in LiSP until
GO is pressed, so you can pick the right block first. If a block triggers several LiSP cues, the first one is started,
and LiSP then starts the others itself.

If the message cannot be sent, for example because the host is unknown, a warning is shown and the button stays
enabled. OSC over UDP is not acknowledged, so the viewer cannot tell whether LiSP actually received the message.

The last cue is only kept while the viewer is running. Disabling the synchronization hides the whole bar.

## Settings

The `Settings` button in the top bar opens the settings window. `OK` applies the changes right away and saves them to
`~/.theatreutils/script_viewer.json` in the home directory of the current user; `Cancel` discards them. The file is read
at every start. If it is missing or contains invalid values, the defaults are used for them.

| Setting | Key in the file | Default | Description |
| - | - | - | - |
| Shown cue lanes | `show_lisp_lane`, `show_x32_lane`, `show_light_cue_lane` | `true`, `false`, `false` | Shows or hides the `LiSP Cues`, `X32 Snippets` and `Light Cues` lanes. Hidden lanes make room for wider text. |
| Cue lane width | `lane_width` | `300` | Width of every cue lane in pixels, from 150 to 600. Narrower lanes leave more room for the text. |
| Current block position | `current_block_position` | `0` | Where the current block is kept within the view, from `0` (top) over `50` (center) to `100` (bottom). Chosen with a slider. |
| Lane letters | `lane_letter_prefixes` | `true` | Labels the cues with the letter of their lane (`L`, `S`, `Q`). If off, all lanes use `#`. |
| Mutes in the LiSP lane | `mutes_in_lisp_lane` | `false` | Additionally lists the X32 mutes and unmutes in the LiSP Cues lane. |
| LiSP synchronization | `lisp_sync` | `false` | Shows the [LiSP bar](#lisp-bar) with the GO button. |
| LiSP OSC address | `lisp_host`, `lisp_port` | `127.0.0.1`, `9000` | Host (IP address or host name) and port LiSP receives OSC on, see [LiSP](lisp.md). Only editable while the synchronization is enabled. |
| GO on Return | `go_on_return` | `false` | The `Return` key presses the GO button, see [Navigation](#navigation). Only editable while the synchronization is enabled. |

## Navigation

| Input | Action |
| - | - |
| Scroll wheel | One block forward / back per notch (touchpad deltas are accumulated) |
| `↓`, `→`, `Space` | Next block |
| `↑`, `←`, `Backspace` | Previous block |
| `Page Down` / `Page Up` | Ten blocks forward / back |
| `Home` / `End` | First / last block |
| Mouse click | Makes the clicked block the current one |
| Part / scene selectors | Jump to a scene |
| `GO` button | Starts the next LiSP cue, see [LiSP bar](#lisp-bar) |
| `Return`, `Enter` | Presses the GO button if GO on Return is enabled in the [settings](#settings) and the GO button is enabled. Otherwise nothing. Holding the key down does not repeat it. |

The `Return` and `Enter` keys are reserved for the GO button and have no other function.

The script document keeps the keyboard focus after using the selectors, the settings or the GO button, so the keys keep
working.

Note that the Space key is also LiSP's default GO key. If the [Buzzer](buzzer.md) is used to trigger LiSP via the
[Serial Keyboard](serial-keyboard.md), the key press goes to whichever window has the focus, so keep LiSP focused
during the show.
